# Offline raw-ledger reconstruction

R90-122 adds `scripts/slo_reconstruct.py`, a standard-library API/CLI that checks
whether supplied adapter observations can be derived from their retained raw
packet/oracle and lifecycle ledgers. Implementation review is **static only**;
behavioral tests and all acceptance runs remain delegated to the specialist
department. No qualifying measurement evidence was generated by the agent.

## Department invocation

Close all source writers before use. This is an unexecuted handoff template:

```bash
python3 scripts/slo_reconstruct.py --adapter retained-run \
  --output-dir reconstruction-review --scratch-dir scratch
```

API: `reconstruct(output, *, adapter=None, max_bytes=64*1024**3,
scratch_dir=None)`, with `pathlib.Path` arguments. `adapter` is the directory
containing [the adapter's five files](slo-collect.md); it can also be the
`adapter/` subdirectory of a retained [evidence bundle](slo-bundle.md).
Omitting it records incomplete evidence. Output must be a new directory with an
existing parent. Scratch is an existing directory for the temporary SQLite
identity index; omission uses the system temporary location. No network, live
traffic, service invocation, resource discovery or external command is involved.

## Retention and reconstruction

1. Copy the fixed `receipt.json`, `manifest.json`, `offered.jsonl`, `events.jsonl`
   and `observations.json` into `adapter/` under the new output. Receipt paths
   cannot select sources. Existing regular-file, non-following open, mutation,
   byte-budget, duplicate JSON member and bounded JSONL checks apply.
2. Validate the original adapter receipt, completion/review flags, inventory
   digests/bytes/rows, manifest and observation schemas, common metadata and run
   identity. Missing, partial, malformed or inconsistent inputs block replay.
   Supplied completion flags cannot bypass freshly checked files.
3. Call the existing adapter on **the retained copies** into `rebuilt/`, passing
the reconstruction input limit through to the collector's cumulative
`max_input_bytes`. This avoids a hidden default-sized second cap when a caller
explicitly chooses a larger reconstruction budget. The collector's input budget
covers manifest/offered/events bytes; it excludes generated outputs and SQLite.
Its
   SQLite correlation enforces packet/event/packet-rule uniqueness, lifecycle
   identity and time ordering, and reconstructs offered/processed/byte counts
   plus all expected alerts. Missing lifecycle values stay null.
4. Bind the new adapter receipt's three source digests/bytes/rows to the retained
   inputs. Validate its output digest/bytes, schema, metadata and run identity.
5. Compare every root observation field. Object member order and JSON whitespace
   do not matter; expected alerts are sorted by unique event ID before comparison.
   All alert identities, values and nulls remain significant. Minute array order
   remains significant. Boolean and numeric JSON representations are distinguished.
   No tolerance, filtering, timestamp adjustment or acceptance waiver is applied.

`observations_match` describes semantic equality after that normalization.
`observation_bytes_match` separately compares original versus rebuilt raw size
and SHA-256; false alone is not a mismatch. Different whitespace/member/alert
ordering can legitimately yield matching observations with different raw bytes.
No full report is created or changed, and failed/inconclusive measurements cannot
be upgraded by reconstruction agreement. The original report still requires the
existing reporter/bundle checks and departmental acceptance review.

## Outputs and outcomes

| Output | Contents |
| --- | --- |
| `adapter/` | Original supplied receipt and four exact retained files, including partial prefixes when available |
| `rebuilt/` | New adapter inputs, reconstructed observations and adapter receipt after successful replay; partial files can remain on error |
| `reconstruction.json` | Published last when possible: original inventory, rebuilt receipt digest/inventory, original/current tool hashes, field comparisons, differences and diagnostic lists |

| Status / exit | Meaning |
| --- | --- |
| `review_required` / 0 | Input checks and reconstruction completed; all observation fields agree; factual review still required |
| `mismatch` / 1 | Invalid or inconsistent evidence, raw identity/time rejection, or reconstructed observations differ |
| `error` / 2 | Local I/O/SQLite operation failure; a final diagnostic receipt may be unavailable if snapshot/publication fails |
| `incomplete` / 3 | Missing, unreadable, nonregular or budget-truncated input prevents reconstruction |

Precedence is error, mismatch, incomplete, review-required. Diagnostics are not
suppressed by the selected status. `reconstruction_attempted` records entry to the
adapter call; `reconstruction_complete` means replay and rebuilt source/output
binding completed, even when semantic comparison differs. Equality fields remain
null unless reconstruction completed. `field_comparisons` and `differing_fields`
identify root fields; inspect both retained observation documents for exact values.
Invalid evidence and resource failures have generic boundary diagnostics without
embedding untrusted record values. The original source digest is retained even
when it differs from the current adapter; current interpretation determines the
rebuild, and changed versions require review.

Every receipt sets `execution_complete`, `facts_verified`,
`comparability_established` and `slo_compliance_asserted` to false, and
`departmental_review_required` to true. Source agreement does not authenticate
acquisition logs, oracle completeness, physical arrival, clock accuracy, durable
storage, process exits or isolation. Coordinated rewriting of inputs and receipts
cannot be detected as false physical evidence by this tool.

## Bounds and persistence

`--max-bytes` defaults to a combined 64 GiB retained-input budget. The original
receipt is limited to 1 MiB, manifest and supplied observations to 64 MiB each,
and JSONL rows to 256 KiB including newline. Files are copied in the fixed order
above; exhausted budgets retain prefixes and block replay. These are input limits,
not a total disk quota. Allow additional space for rebuilt manifest/ledger copies,
up to 64 MiB rebuilt observations, generated metadata and the temporary SQLite
index. Disk use and processing time grow with packet count. In-memory JSON
validation/comparison scales with the bounded observation documents; actual
performance and memory use are unmeasured.

Output, adapter and rebuilt directories are private (0700 subject to umask).
Original snapshots are 0600; rebuilt raw files follow existing adapter/umask modes
inside their private directory. File writes are exclusive and synced; child
entries are synced before publishing the final reconstruction receipt, then the
output parent's entry is synced. Publication is not an atomic directory
transaction. Late write/fsync/close errors can leave visible receipts; inspect
process exit too. Preserve all partial output and retry to a fresh destination.
The temporary SQLite index is cleaned by the adapter; retained evidence is never
automatically deleted. Inputs/output directories must remain quiescent and trusted;
these checks are not protection against an adversarial concurrent filesystem owner.

## L1：小流量实时检测，两轮独立执行

以下为本次冻结的起始门槛，**不是已测得的能力**。

| 参数 | local-v1 门槛 |
| --- | --- |
| 规则 | 固定 100 条不同的启用 payload 规则，每条一个有界关键词；三种规则类型的功能覆盖由 L0 承担 |
| 每轮持续时间 | 600 秒，另有 30 秒停止发包后的观察/排空窗口 |
| 发包速率 | 常态 100 pps；第 180–239 秒和第 480–539 秒为 500 pps 突发，各 60 秒 |
| 每轮计划包数 | 108,000；保存调度时间、真实 offered/submitted/completed，不以计划数冒充实际数 |
| 包与正例 | 未标 VLAN 的 Ethernet/IPv4/非分片 UDP，目标平均帧长约 512 字节，记录真实均值；每秒一个独立预期告警，600 个预期事件 |
| 漏报/额外告警 | 每轮缺失预期告警为 0，非 oracle 预期告警为 0；记录实际事件身份，不用聚合行数替代事件数 |
| 包丢失 | 每轮常态、每个 60 秒突发分别 <=1%；分母为独立 offered 的合格包，重复不能增加完成数 |
| 延迟 | 主机 libpcap 入站时间戳至 FULL-synchronous WAL 成功返回，p99 上界 <=500ms；采样和时钟要求见下文 |
| 重复性 | 两轮分别创建新工作目录、状态、端口/UDS 和 run ID；各自通过，不能取最好结果 |

速率改以 pps 为主，不再强求 Mbps/Gbps。600 个正例是明确增加的本地合成工作负载，
不能沿用旧基线“15 条告警/分钟”的称谓。只对冻结的规则和载荷 oracle 证明正确性。

### 测量有效性与失败处理

- 捕获、发包和引擎使用同一 VM 的时钟；保留时钟阶跃/异常检查、分辨率与误差
  证据。误差上界须可建立且 <=10ms；判定使用 `p99 + 误差上界 <=500ms`。
  该边界是主机时间戳至持久化返回，不声称物理网卡到包延迟或抗断电保证。
- 所有预期事件均进入分母，缺失完成时间按正无穷参与最近秩 p99，并直接因漏报
  失败；保留原始计数、晚到、未完成、重复和出错事件，分别报告常态/各突发。
- 停止 offered 后保留 30 秒观察，确认队列和持久化完成后才停止被测进程；
  引擎退出不保证排空队列。超出观察窗口的事件仍计入晚到/缺失，不能直接删掉。
- 冻结真实 offered 与计划的允许偏差为每个一分钟窗口 +/-5%；出现生成器错误、
  无法达到速率、缺少时钟证据或采集不完整时记录 `inconclusive`/无效测量。
  数值失败仍保留，不能因“无效”而隐藏。缺失预期事件必定不能通过。
- 规则/配置/源码和工具哈希、完整原始 ledgers、SQLite 持久化观察、实际资源及
  offered 调度必须保留。只看 API 健康、进程退出码或 reporter 返回 0 不构成通过。
- 门槛失败先定位性能或正确性原因；如确需再降目标，须在新执行前单独修订契约
  版本并保留失败证据，不能事后改本轮门槛或缩减分母。

## L2：30 分钟稳定性与可恢复性

使用相同 100 条规则、常态 100 pps、每秒一个预期事件，累计 offered 时间为
1,800 秒。完成一次停止发包/排空后的优雅重启和一次 UDS 断连重连；停发维护段
单独计时并保留，不计入这 1,800 秒 offered 时间。恢复后先证明 ready 再继续发包。
不将突然断电或高负载强杀恢复作为本轮新增验收目标。

通过条件：无 panic/race/ASan finding、无恢复前后告警丢失或事件重复、无损坏的
SQLite/recovery 输入；持久化观察、API 查询与 oracle 一致。正常工作段按 L1 的
丢包/漏报/延迟门槛验收。SUT 进程组峰值 RSS <=3 GiB、生成器 <=1 GiB，记录
采样间隔与峰值，不能仅用开始/结束两个点代替峰值观察。写满磁盘不得伪装成功。

## 现有机器的执行预算

- SUT 最多使用 4 个逻辑 CPU、3 GiB 内存；生成器最多 2 个逻辑 CPU、1 GiB。
  记录实际限制/亲和性与争用；这些是共享 VM 内预算，不是独占硬件保证。
- 执行前至少 8 GiB 可用磁盘，所有本轮证据累计预算 4 GiB。计入原始文件、
  重建/比较副本、数据库、临时 scratch 和日志，不能只限制单个输入。
- 若 OS/其他工作负载导致预算无法满足，保留 preflight/inconclusive 原因，
  降低并发或单独安排执行时段；不要求用户购买新机器来继续开发。
- 保持新目录、端口、UDS、数据库、输出与进程组隔离；清理仅针对本次创建的
  对象，不复用或清理其他服务，不依赖外网接口发包。
